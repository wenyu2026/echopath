# EchoPath · 来路 —— UI 构想案例 + 视觉操控台（文字版 V1）

> 用途：这份文件是以后我们改 UI 的"控制台说明书"。
> 你不需要懂代码，只要照着"控制台"里的名字跟我说话，我就能精准改界面。
> 例：你说"把果冻模糊调大一点、决策页的线点分叉升到 3 级"，我就知道改哪几个参数。

# 第〇部分 · 先建立一个概念：什么是"设计变量"（Design Token）

以后我们所有的 UI 调整，本质都是在改一组**变量**：

- 颜色不是"那个绿"，而是一个变量 `--green`，全站所有绿色都听它的；
- 果冻质感不是"那个效果"，而是 4 个变量：透明度、模糊度、圆角、阴影；
- 动效不是"那个动画"，而是 2 个变量：时长、缓动曲线。

**好处：改一个变量 = 全站同时改。** 这就是"操控台"的原理：
你在控制台上拨一个开关，整个产品一起变，而不是一页一页手工改。

这套方法是行业标准做法（W3C 设计令牌规范、Figma 变量功能都是这个思路，链接见文末）。

# 第一部分 · 把你的构想落成 3 个页面案例（文字版）

## 案例 A：首页（第 01 页）

**作用**：让用户愿意开始。不解释功能，只传递一种感觉——"它不是算命，也不是直接给答案"。

```
┌──────────────────────────────────────────────────────┐
│  EchoPath · 来路                            关于  ○  │  ← 极轻的顶栏
│                                                      │
│      让前人的来路，                                   │
│      成为后来者看向未来的回响。              · · ·      │  ← 背景有几条极淡
│                                          ·      ·     │    的路径线，汇向
│      不是预测你的未来，                    ·  YOU NOW · │    NOW 点后向未来
│      而是让你看见别人已经走过的未来。        ·      ·   │    淡出
│                                                      │
│      开始梳理我的来时路  →                            │  ← 文字式轻按钮
└──────────────────────────────────────────────────────┘
```

**这个案例的控制台预设值**：

| 控制项 | 设定 |
|---|---|
| 背景 | 暖米白 `--paper` |
| 大标题 | 衬线人文体，最大字号，石墨黑 |
| 线点分叉 | Level 1（几乎不可感知，只做品牌气氛） |
| 果冻质感 | 本页不用 |
| 动效 | 路径线缓慢"生长"出来，约 1.2 秒，之后静止 |
| 照片 / 插画 | 不用 |

## 案例 B：个性化决策地形页（第 04 页）

**作用**：这是全线产品里"线点分叉"唯一当主角的页面。把相似人物真实走过的选择，抽象成这个用户眼前的 2–4 条路。

```
┌──────────────────────────────────────────────────────────┐
│ ▓ 纵向果冻导航（当前项"决策地形"是绿色果冻胶囊）            │
│                                                          │
│   在与你来时路比较接近的人中，我们看到了这些不同的走法：      │
│                                                          │
│                        ╭──── 守住已经建立的路径            │
│                       ╱      保护：已投入的两年             │
│   你的来时路 ───●────┤       代价：方向可能长期不匹配        │
│      (NOW)          ╲      4 个真实案例走过这条路 →         │
│                      ╰──── 现在换道                         │
│                            保护：长期方向匹配               │
│                            代价：已有投入无法全部收回        │
│                            3 个真实案例走过这条路 →         │
│                                                          │
│   ┌─ 果冻状态块 ─────────────────────────┐                 │
│   │ 正在根据你刚才的回答重新计算代价排序…  │                 │
│   └──────────────────────────────────────┘                 │
└──────────────────────────────────────────────────────────┘
```

**关键规则**：

- 人名、相似度分数**不上这一页**。第一屏只讲：每条路保护什么、代价是什么、后来发生了什么。
- 代价排序是**个性化**的（用户更怕"再次选错"，就把"再次选错"排第一）。
- 路径分叉用柔和曲线，不用工程直线，避免像流程图。

**控制台预设值**：线点分叉 **Level 3**（全站仅此页）；果冻质感用于导航 + AI 状态块；强调色木橙只标"当前节点"。

## 案例 C：人物深阅读页（第 05 页）

**作用**：让用户真正"走进"一个真实人生，而不是看标签。编辑式排版在这里发挥最大作用。

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   41 岁的时候，他已经不是第一次想离开了。        ┌───────┐ │
│                                          │ 人物  │ │
│   一句短引言，单独占一大片空间，             │ 肖像  │ │
│   让读者先停下来。                         └───────┘ │
│                                                          │
│   1906 ─────────────────────────────                     │
│                                                          │
│   在这之前，他已经几次进入官场，也几次离开。               │
│   对他来说，问题已经不再是"能不能做官"。                   │
│                                                          │
│         "他当时并不知道，这会成为后来人                    │
│          定义他一生的选择。"                ← 重要引用     │
│                                                          │
│   他当时已经知道什么                                      │
│   他不知道什么                                           │
│   他做了什么                                             │
│   后来发生了什么                                          │
└──────────────────────────────────────────────────────────┘
```

**关键规则**：

- 不做"人物信息卡"（生于某年 / 相似度 82% 这种不上台面）；
- 按人的阅读顺序讲：来路 → 路口 → 知道什么 / 不知道什么 → 做了什么 → 后来；
- 内容原则：准确史实 + 文学化叙事 + 明确证据边界（史实不能编，但故事要讲得有人味）。

**控制台预设值**：线点分叉 Level 2（细时间线）；内容密度拨到"编辑式"一端；无卡片，只用细线分隔。

# 第二部分 · EchoPath 视觉操控台（你以后用来指挥我的面板）

操控台分 7 个模块。每个控制项都写清：中文名 / 变量名 / 默认值 / 可调范围 / 调大调小的效果 / 风险提醒。

## A. 色彩控制台

| 中文名 | 变量名 | 默认值 | 可调范围 | 效果说明 |
|---|---|---|---|---|
| 纸张底色 | `--paper` | 暖米白 #F7F4EE | 白 ↔ 米 ↔ 浅奶油 | 越暖越像书房，越白越像工具 |
| 正文墨色 | `--ink` | 石墨黑 #2B2A26 | 纯黑 ↔ 暖灰 | 纯黑太硬，建议保持略暖 |
| 主品牌绿 | `--green` | 灰橄榄绿 #6F7F5E | 偏黄 ↔ 偏蓝、饱和低 ↔ 高 | 决定整个产品的"性格" |
| 强调木橙 | `--wood` | 蜂蜜棕 #B97D46 | 焦糖 ↔ 珊瑚 | 只给关键节点用，大面积会闹 |

## B. 质感控制台（果冻 = Apple 式材质语言）

| 中文名 | 变量名 | 默认值 | 可调范围 | 效果说明 |
|---|---|---|---|---|
| 果冻透明度 | `--jelly-opacity` | 55% | 0–100% | 越低越"透"，太高会看不见材质感 |
| 果冻模糊 | `--jelly-blur` | 16px | 0–30px | 越大越柔，太大会脏 |
| 果冻圆角 | `--jelly-radius` | 20px | 8–32px | 越大越"软" |
| 果冻阴影 | `--jelly-shadow` | 轻 | 无 / 轻 / 中 | 决定浮起的高度感 |

**原则**：果冻只出现在"活的、正在变化"的地方。它一泛滥，记忆点就没了。

| 中文名 | 变量名 | 默认值 | 可调范围 | 效果说明 |
|---|---|---|---|---|
| 标题字体性格 | `--font-display` | 衬线人文 | 衬线 ↔ 无衬线 | 衬线像书，无衬线像工具 |

## D. 线点分叉控制台（品牌视觉母题）

| 中文名 | 变量名 | 默认值 | 可调范围 | 效果说明 |

## E. 动效控制台

| 中文名 | 变量名 | 默认值 | 可调范围 | 效果说明 |
|---|---|---|---|---|
| 快动效 | `--motion-fast` | 180ms | 100–250ms | 按钮反馈、悬停 |

# 第三部分 · 即时调控 UI 的基础知识（给非计算机专业的你）

以下每条都配了权威来源，你可以只看加粗的结论。

## 1. 设计变量（Design Token）——"操控台"为什么可行

行业正在把"颜色 / 字号 / 圆角 / 阴影"统一成一种叫**设计令牌**的标准数据格式（W3C 社区规范草案）。
**结论：界面的一切外观都可以变成变量，改变量就等于改全站。** 所以你以后跟我说"绿一点""透一点"，我改的是一个变量，不是一百个地方。

## 2. CSS 变量——网页上"边调边看"的原理

浏览器原生支持自定义属性（CSS Variables）：定义一次，处处引用，改一处立即全页刷新。
**结论：我们完全可以做一个带滑杆的预览页，你拖滑杆，界面实时变。** 这不是黑科技，是浏览器的标准能力。

## 3. 对比度底线（WCAG 无障碍标准）

国际标准规定：普通文字与背景对比度至少 **4.5:1**，大字号文字至少 **3:1**，界面组件（图标、边框、控件）至少 **3:1**。
**结论：这是我们调色时的硬约束。** 你可以往"安静、浅淡"调，但碰到这条线我会提醒你"再浅就有人看不清了"。

## 4. Apple 材质语言（你喜欢的"果冻感"的官方说法）

Apple 人机界面指南里的 **Materials / Vibrancy（材质与鲜亮效果）**：半透明 + 背景模糊 + 内容自动适配深浅色，用来表达"层级"和"前景内容"，而不是装饰。
**结论：果冻感的正统用法 = 只给浮层和当前状态用。** 这和我们定的"果冻只做导航和 AI 状态"完全一致。

## 5. 动效的三要素（Material Motion）

任何动画都由三件事决定：**时长**（快 100–250ms / 中 250–400ms / 慢 400ms+）、**缓动曲线**（先快后慢最自然）、**触发原因**（用户操作还是系统主动）。
**结论：你以后说"动画太飘 / 太肉"，我会翻译成"调时长还是调曲线"，两个旋钮就能解决。**

## 6. 减少动态（prefers-reduced-motion）

操作系统允许用户声明"我晕动效"，网页必须能响应这个设置。
**结论：我们要留一个总开关，开了之后路径生长、果冻滑动全部降级为淡入。** 这是专业产品的必修课。

## 7. Figma 变量——设计稿里的同款操控台

Figma 的 Variables 功能和网页的 CSS 变量是同一个思想：设计师改变量，所有画板同步更新，还能一键切主题。
**结论：以后我们的"控制台参数表"可以同时映射到代码和 Figma 稿，两边不会打架。**

# 第五部分 · 需要"添加新元素"时，怎么跟我沟通

先明确分工，避免误会：

- **控制台（线上滑杆）只是"试感觉"的工具**，不是你必须自己做的活。它负责"调"——调整已经存在的东西的参数。
- **所有正式的修改都由我来改代码**。你随时可以完全不用控制台，只用大白话跟我说。
- **"加新元素"不属于控制台**，它走下面的"元素需求卡"流程：你描述 → 我先给文字版确认 → 你点头 → 我改 demo → 新元素涉及的可调参数会自动加入控制台。

## 元素需求卡（你只需要回答六件事，能答几件算几件）

1. **它叫什么**：你自己起的名字就行，不用专业术语。例："今日一句"。
2. **放在哪**：哪一页、大概哪个区域。例："首页大标题下面"。
3. **里面有什么**：内容从哪来、是固定的还是变化的。例："每天换一句人物说过的话"。
4. **用户能对它做什么**：能点吗？点了去哪？还是只能看？例："只能看，不能点"。
5. **它什么时候出现 / 有几种样子**：一直显示？还是某种状态下才出现？例："每次打开都在"。
6. **它有多重要**：希望用户一眼看到，还是顺带看到？（这决定它的视觉层级）
7. **怎么触发**：用户做什么动作它才反应？（悬停 / 点击 / 停留片刻 / 自动）
8. **不能破坏什么**：改动时哪些现有体验必须保住。例："聊天区不能突然跳动"。

有参考图或"像某某产品的某个东西"也可以直接丢给我。

## 示例：一句话需求 → 我怎么理解

**你说**："首页加一个'今日一句'，每天换一句人物的话。"

**我自动补全并跟你确认**：

- 位置：首页副文案之下、开始按钮之上；
- 视觉层级：低于主标题，用衬线小字 + 细线，不加卡片；
- 控制台新增参数：`quote-visible`（开/关）；
- 动效：每次打开页面淡入 560ms，减少动态开启时直接显示；
- 内容规则：沿用"有证据的叙事化表达"，只放人物真实留下的文字。

**你说**："决策页我想能'收藏某条路'。"

**我会追问两个关键问题**：收藏之后在哪里看到？收藏这个动作会不会改变路径的排序？——然后同样先给文字版，再动 demo。

## 你完全可以说"半成品"需求

比如"我觉得人物页右边空，想放点啥但不知道放啥"。
这时我会给你 2–3 个候选方案，每个都写清：它解决什么、会不会破坏"编辑式极简"、需要新增哪些控制台参数。你选一个，或者全否掉。

# 第六部分 · 范式验证：这次的 4 条需求能不能用元素需求卡提问？

结论：**能，但元素需求卡需要补两个字段**（已补：第 7 问"怎么触发"、第 8 问"不能破坏什么"）。
因为这次 4 条里有 3 条是"改交互"而不是"加元素"，交互需求必须说清触发方式和约束。

## 逐条归类

| 需求 | 叫什么 | 放在哪 | 用户能做什么（交互） | 怎么触发 | 不能破坏什么 |
|---|---|---|---|---|---|
| 1. 目录跟随鼠标 | 高亮跟随胶囊 | 左侧目录 | 悬停预览高亮，点击才切页 | 鼠标悬停 / 离开回到当前页 | 目录文字稳定不动；当前页始终可辨认 |
| 2. Apple 式柔软质感 | 果冻材质升级 | 导航与可点元素 | 移动微拉伸、停下恢复、点击轻压回弹 | 指针移动与按下 | 文字辨认；减少动态模式下要降级 |
| 3. 可收起的垂直标签 | 目录收放 | 页面左缘 | 点拉手展开、点收起按钮收回 | 点击（触屏可用） | 聊天区不突然跳动 |
| 4. 来路便签 | 聊天缩影便签 | 来时路页聊天区右上侧 | 看、修改、删除不准确条目 | 发送消息后增量更新 | 不挡对话与输入框；不编造用户没说过的经历 |

## 用卡片格式重写第 4 条（示范）

1. 叫什么：来路便签（聊天缩影）
2. 放在哪：来时路页，聊天区右上侧，轻微浮起
3. 里面有什么：从聊天提炼的来路——走到这里的原因 / 转折 / 看重的 / 卡住的 / 待确认
4. 用户能做什么：看、改、删；窄屏时点"我的来路"入口展开
5. 什么时候出现：随聊天逐步长出，开始时几乎为空
6. 有多重要：辅助层，文字聊天仍是第一视觉层
7. 怎么触发：每次发送消息后，有新信息才更新
8. 不能破坏什么：不能挡对话；不能推断用户没说的内容；输入过程中不闪动

## 范式结论

- **加元素** → 元素需求卡 1–6 问足够。
- **改交互 / 改质感** → 必须加第 7 问（怎么触发）和第 8 问（不能破坏什么）。
- **改内容规则**（例如便签"不编造"）→ 属于内容原则，单独写一条，不和 UI 混在一起。

这次你的提示词里其实已经天然包含了这些字段，只是散落在段落里；用卡片重写一遍，以后提需求会更快、更少歧义。
