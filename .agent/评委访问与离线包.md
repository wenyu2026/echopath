# 评委访问与离线材料准备

> 目的：仓库是私有的 —— 评委看不到代码，工程化优势（71 项单测、preflight、变异测试、断网兜底）就全部浪费。
> 本文件列出三种给评委看代码的方式，**按省事程度排序，至少做 A**。
> ⚠️ **所有打包动作必须在全部改动合并之后做**（和备用演示视频同一天），否则包里是旧代码。

---

## 方案 A：git bundle 离线包（推荐，零网络依赖）

一个文件包含全部历史 + 所有分支，评委解包即可浏览，**不需要 GitHub 权限、不需要网络**。

```bash
# 在仓库根目录（全部合并后执行）
git bundle create ../echopath-20261002.bundle --all --branches

# 验证包可用（应列出 master 等分支）
git bundle verify ../echopath-20261002.bundle

# 评委侧打开方式（发给评委的一行说明）：
git clone echopath-20261002.bundle echopath
```

拷贝位置：**U 盘 + 演示电脑桌面各一份**（和备用视频放一起）。

## 方案 B：源码 zip 快照（给不想碰 git 的评委）

```bash
git archive --format=zip --output=../echopath-src.zip HEAD
```

只有当前快照没有历史，但打开就能读，适合发微信/邮件。

## 方案 C：GitHub 权限（如果评委愿意登录）

- 给评委的 GitHub 账号开 collaborator：Settings → Collaborators → Add people。
- ⚠️ 个人私有仓库的 collaborator 是**写权限**，若需要只读，临时把仓库设 public 最省事，赛后再改回 private。

## 配套材料清单（装同一个 U 盘）

| 材料 | 生成方式 | 时机 |
|---|---|---|
| 90 秒备用演示视频（实时 + 断网两条流程） | 按 [.agent/DEMO.md](DEMO.md) 逐拍脚本录屏 | **全部合并后** |
