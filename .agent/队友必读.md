## 3. 第 2 步：解决网络（关键）

**本赛场直连 GitHub 基本不通**（实测：卡 75 秒后 `Failed to connect to github.com port 443`）。

**所以必须先配代理**，否则后面所有 git 操作都会卡死。

### 你首先要有代理

Clash / Clash Verge 之类的工具，**记住它的混合端口**（通常是 `7890`）。

**确认代理在跑**（Windows PowerShell）：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 7890
```

- **有输出** = 代理正常 ✅
- **无输出** = 代理没开，先打开它

### 让 git 走代理

```bash
git config --global http.https://github.com.proxy http://127.0.0.1:7890
```

> 把 `7890` 换成你自己的端口。

**只让 GitHub 走代理**，Gitee 和国内站点不受影响。

### 验证

```bash
git config --global --get http.https://github.com.proxy
```

能打印出你刚设的地址就对了。

## 4. 第 3 步：克隆仓库

### 方式 A：SSH（**推荐**，一次配好永久有效）

```bash
# 1. 生成密钥（如果还没有）
ssh-keygen -t ed25519 -C "你的GitHub邮箱"
# 一路回车即可，不用设密码

# 2. 复制公钥（Windows PowerShell）
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | Set-Clipboard

# 3. 贴到 GitHub
#    浏览器打开 https://github.com/settings/keys
#    点 New SSH key → Title 随便填 → Key 粘贴 → Add SSH key

# 4. 克隆
git clone git@github.com:wenyu2026/xuejun-hackathon.git
```

### 方式 B：HTTPS + 自己的 Token

```bash
# 1. 生成 Token
#    浏览器打开 https://github.com/settings/tokens
#    Generate new token (classic)
#    勾选 repo  →  有效期设 7 天  →  生成后立刻复制（只显示一次）

# 2. 克隆
git clone https://github.com/wenyu2026/xuejun-hackathon.git
#    提示输入时：
#      用户名 = 你的 GitHub 用户名
#      密码   = 粘贴刚才的 Token（不是账号密码！）
```

**克隆完进入目录**：

```bash
cd xuejun-hackathon
```

## 8. ⚠️ 私有仓库认证（重要）

这一节专门讲**你 AI 很可能会踩的坑**。

### 坑 1：`Repository not found` ≠ 地址错了

私有仓库对**匿名**访问**一律**返回：

```
Repository not found
```

**这是 GitHub 故意的** —— 防止别人探测某个仓库是否存在。

**所以如果你看到这个提示，正确结论是「我没带身份」，不是「地址写错了」。**

**证据**：同一个地址，匿名访问是 404，带认证访问是 200。

### 坑 2：镜像加速代理对私有仓库无效

`gh-proxy.com` 之类的镜像**是匿名加速器**，它自己没有你的身份，**拿不到私有仓库**。

```
公开仓库 → 镜像能拿到        ✅
私有仓库 → 镜像永远 not found  ❌
```

**而且不要把私有代码往第三方镜像传**，有泄露风险。

### 坑 3：🚫 不要向任何人索要 Token

**别跟队长要 Personal Access Token，也别把自己的给出去。**

| 原因 | 说明 |
|---|---|
| Token = 账号密码 | 拿到就能读**所有**私有仓库，不只是这一个 |
| 无法追溯 | 通过聊天传出去，谁用过查不到 |
| **没必要** | 你**自己**就是协作者，生成**自己的** token 就行 |

**要认证就用第 3 步的 SSH 或自己的 token。**

### 坑 4：认证和网络是两件事

| 问题 | 症状 | 解决 |
|---|---|---|
| **权限**问题 | `Repository not found` | 用 SSH / 自己的 token（第 3 步） |
| **网络**问题 | 卡住 / `Failed to connect` / `curl 35` | 配代理（第 2 步） |

**两个都要解决，互不替代。** 认证对了但没配代理，照样连不上。

## 9. 排错手册

| 现象 | 原因 | 解决 |
|---|---|---|
| `Repository not found` | 私有仓库 + 匿名访问 | 用 SSH 或自己的 token（第 3 步） |
| 卡 75 秒后 `Failed to connect ... port 443` | 没配代理 | 第 2 步配代理 |
| `curl 35` / `connection reset` | 网络抖动 | **直接重跑**，Git 不会传坏数据 |
| 提示输入密码 | 用了 HTTPS 且没 token | 密码栏粘贴 **token**，不是账号密码 |
| `Authentication failed` | token 过期/权限不够 | 重新生成 token，勾 `repo` |
| 打开仓库地址看不到 | 邀请没接受 | 回第 2 步点 Accept |
| 打不开 github.com（浏览器） | 系统代理没开 | 开 Clash 的「系统代理」开关 |
| 终端中文乱码 | PowerShell 5.1 编码问题 | 加 `-Encoding UTF8`，**文件本身没坏** |
| AI 说读不到 AGENTS.md | 不在仓库目录 / 没拉最新 | `cd` 到仓库目录，`git pull` |

### 一键自检（Windows PowerShell）

在仓库目录执行，能同时看到网络和仓库状态：

```powershell
Write-Host "代理端口 7890:" -NoNewline
if (Get-NetTCPConnection -State Listen -LocalPort 7890 -ErrorAction SilentlyContinue) { Write-Host " 正常" } else { Write-Host " 未监听 → 先开 Clash" }

Write-Host "git 代理配置:" -NoNewline
$p = git config --global --get http.https://github.com.proxy
if ($p) { Write-Host " $p" } else { Write-Host " 未配置 → 见第 2 步" }

Write-Host "提交身份:"
Write-Host ("  name  = " + (git config --global --get user.name))
Write-Host ("  email = " + (git config --global --get user.email))

Write-Host "远程连通性:"
git ls-remote origin HEAD 2>&1 | Select-Object -First 1
```

## 10. 协作速查

### 你要遵守的 5 条

| # | 规则 |
|---|---|
| 1 | **不许直接 push `master`**，用自己的分支 `<用户名>/<简述>` |
| 2 | **不许自己 merge PR**，必须由人类决定 |
| 3 | **不许提交 `package-lock.json`** |
| 4 | **说"完成"之前必须查 Issue**（见下） |
| 5 | **不许提交 `.env` 或任何密钥** |

### 说「完成」之前必须跑这两条

```bash
gh issue list --label "agent:blocked" --state open
gh issue list --assignee "@me" --state open
```

> ⚠️ `mentions` 有约 5 秒索引延迟，刚发的提及可能查不到 ——
> **别据此断定"没人找我"。**

### 5 种消息格式（发在 Issue 评论里）

| 格式 | 什么时候用 |
|---|---|
| `CHECKIN` | 领取任务时 |
| `BLOCKED` | 卡住了（**必须写清：等谁 / 等什么 / 我还能做什么**） |
| `HANDOFF` | 交接给别人 |
| `DONE` | 完成时 |
| `REVIEW` | 请求审查 |

**详细格式见 [`AGENTS.md`](../AGENTS.md) 第 3 节。**

### 最常犯的错

| ❌ 别做 | ✅ 应该做 |
|---|---|
| 闷头做完才吭声 | 每个阶段都在 Issue 里同步 |
| 卡住了硬扛 | 立刻发 `BLOCKED` |
| 改别人区域的代码 | 先发 `CHANGE_REQUEST` 等对方 `OK` |
| 一个 PR 塞一堆改动 | 一个 PR 只做一件事 |
| 提交锁文件 | 只改 `package.json`，锁文件归集成者 |
