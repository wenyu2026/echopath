## 0. 执行摘要：我们到底在做什么

我们不是在做一个“历史人物聊天机器人”，也不是做一个“AI 替你规划人生”的算命式工具。我们要做的是一种新的经验检索方式：把一个人的过去经历、当前困境与现实约束结构化，再从历史人物、近现代人物、公开传记与真实案例中检索出一批真正处在相似人生路口的人，展示他们当时面对什么、为什么这样选、后来经历了什么、最终走向哪里，以及他们和用户“像在哪里、又不像在哪里”。
产品最终服务的不是“答案”，而是“认知地图”。用户不是来问“我该不该转专业”，而是来理解：像我这样的人，曾经有人坚持、有人转向、有人先试探再转向；这些选择分别付出了什么代价、带来了什么可能结果，我能不能接受。

**[表 2]**

| 产品本质 把“别人的人生经验”从散落在书、访谈、传记和个人叙述里的非结构化信息，变成可搜索、可比较、可追溯、可反思的“人生经验基础设施”。 |

对用户：降低“阅历不足导致的盲区”，不是替他决策，而是让他借用他人的经验。
对技术：核心不是一个 Prompt，而是“画像 + 决策状态建模 + 经验事件数据库 + 混合检索 + 重排 + 分叉选择 + 证据追踪 + 反类比”。
对数据：第一批可以优先使用史料完整、公开可验证的人物作为冷启动，不把“历史”限制成最终边界。
对商业：C 端重大人生决策低频，因此长期更适合走高校生涯教育、通识教育、咨询工具和经验 API/B2B2C。
对主题：回应“你希望教育如何对待下一个像你一样的人？”——教育不只应该告诉后来者“应该怎么做”，也应该让他们看见前人真的怎样做过、付出了什么代价。

## 1. 思路演化：我们为什么从“工作台/社区”走到“经验智能”

团队最初的讨论看起来很发散，但实际上存在一条清晰的收敛路径。每一次“否定前一个点子”，都在把问题从表层功能推向更深层的用户需求。

**[表 3]**

| 阶段 | 当时想解决的问题 | 为什么不够 | 留下来的价值 |
| 工作台 / 任务池 | 我今天要做什么、什么时候做 | 与成熟 Todo、日历、课表工具差异小 | 用户需要“方向”，不只是“安排” |
| 高质量大学生社区 | 信息太碎、低质内容太多 | 冷启动、内容生产、审核、商业化、技术壁垒都重 | “经验”比普通信息更有价值 |
| 历史人物聊天 | 现实经验难收集，历史人物已有完整经历 | 人物聊天、Persona RAG 已有大量类似项目 | 史料可以成为可信的冷启动经验库 |
| 历史经验检索 | 从历史里找和我类似的人生选择 | 若只找“像的人”，容易硬套和成功学 | 需要相似 + 差异 + 证据 + 多分叉 |
| Experience Intelligence | 让别人的经验变成自己的认知资产 | 需要长期建设数据资产与匹配体系 | 形成真正可持续的产品边界 |


**[表 4]**

| 关键转折 产品不再问“AI 能给我什么建议”，而是问“人类已经有哪些真实经验，只是过去太难检索、太难比较、太难代入到我身上？” |


## 2. 产品定义：来路 / EchoPath

推荐将产品层名称暂定为“来路（EchoPath）”，技术层称为“Experience Intelligence / 经验智能”，底层数据单位称为“Decision Episode / 人生决策事件”。“问史”可以保留为历史数据版本的 Demo 名称，但不要把最终产品限制成“历史 App”。

**[表 5]**

| 一句话产品定义 一个把“别人的人生经验”变成可搜索、可比较、可展开的人生路径地图，让用户在做选择前先看见不同选择曾经把相似的人带向哪里。 |

更口语的版本：你不是来问 AI “我应该怎么选”，而是先把自己的来时路告诉它；AI 帮你找出一批和你走到过相似路口的人，再把他们后来走向的不同分叉展开给你看。
最重要的边界：系统不预测你的未来，不给“最佳路线”，不输出“你有 78% 概率成功”。它提供的是案例、差异、代价与可接受结果的比较。

## 3. 用户问题与目标人群

“所有迷茫的人”不是可执行的目标用户。比赛阶段必须明确第一用户：有行动意愿、但在关键选择上缺少足够阅历与可比较案例的大学生。

**[表 6]**

| 人群 | 典型场景 | 为什么需要 | 使用频次 | 阶段优先级 |
| 大一/大二学生 | 转专业、科研/竞赛、探索还是专注 | 第一次面对非标准答案选择，阅历少 | 低到中频 | 最高 |
| 大三/大四学生 | 考研/就业/转行、城市/行业选择 | 选择代价增大，需要对比长期路径 | 低频但高价值 | 高 |
| 职业早期 1–5 年 | 跳槽、换行业、创业/稳定 | 现实约束更多，愿意看同类案例 | 低频高价值 | 中 |
| 高校教师/辅导员/生涯中心 | 新生教育、通识、生涯课程 | 需要具体案例而非空泛说教 | 课程型复用 | 中长期 |
| 咨询/内容/教育平台 | 给用户提供经验类案例 | 需要结构化经验库与检索能力 | API/工具调用 | 长期 |

第一版用户画像建议：18–24 岁；遇到“坚持还是转向”“探索还是专注”“稳定还是冒险”“我要不要继续投入”等问题；不满足于“网上一句大道理”，愿意花 3–8 分钟补充自己的经历与约束。

**[表 7]**

| 核心 Job-to-be-Done 当我站在一个我没有经历过的人生路口时，我希望快速知道：和我过去很像的人曾经怎么选、为什么这样选、最后付出了什么代价和获得了什么，从而判断哪些结果是我愿意承受的。 |


## 4. 和 MBTI、职业测评、ChatGPT 的关系

团队讨论中提出“它可能有点像 MBTI”，这个类比是有价值的，但要明确：相似的是“帮助用户理解自己”，不同的是“我们不是给你贴一个稳定人格标签”。

**[表 8]**

| 维度 | MBTI / 性格测评 | 普通 AI 建议 | 来路 / EchoPath |
| 核心问题 | 你是什么类型？ | 你应该怎么办？ | 像你这样走到这个路口的人，后来走向了哪里？ |
| 输入 | 问卷答案 | 当前问题文本 | 过去经历 + 当前路口 + 约束 + 价值偏好 |
| 输出 | 人格标签/描述 | 生成式建议 | 相似案例组 + 选择分叉 + 结果 + 差异解释 |
| 时间性 | 相对静态 | 单次问题 | 动态：你的状态变化，匹配结果也变化 |
| 证据来源 | 心理测量框架 | 模型知识与推理 | 结构化真实经验与来源 |
| 决策角色 | 理解自我 | 容易替用户给结论 | 提供镜子，不代替选择 |
| 核心体验 | “原来我是这种人” | “AI 建议我这样做” | “原来有人和我这么像，但他们走出了完全不同的路” |


**[表 9]**

| 最好的一句区分 MBTI 在回答“我是谁”；我们在回答“我现在在哪里，别人从这里去了哪里”。 |

因此，产品可以借鉴 MBTI 的低门槛入口：通过 6–12 个有趣的问题快速建立“当前人生画像”，但不要宣称测出稳定人格，更不要使用伪精确的人格百分比。

## 5. 核心产品机制与用户流程

产品必须围绕一个核心体验：从“我现在很抽象地迷茫”到“我能看到几条别人真实走过的路径，并知道哪些地方值得参考、哪些地方不能照搬”。
1. 建立“来时路”：用短问答或自然语言，让用户描述过去 2–5 个关键节点、做过的选择、持续投入、兴趣变化与现实条件。
2. 识别“当前路口”：AI 把用户当前困境结构化为核心冲突、目标、约束、风险承受、可逆性、时间窗口等。
3. 检索“相似人生事件”：不是检索整个人，而是检索某个人在某个时间段的一次关键选择。
4. 强制“多分叉”：输出不只是最像的三个案例，而是尽量覆盖不同决策路径，例如坚持、立即转向、先验证再转向。
5. 展示“结果链条”：短期结果、中期结果、长期结果、后续新的关键节点，而不是一个简单的“成功/失败”。
6. 解释“像与不像”：对每个案例列出关键相似点与结构性差异，避免把历史或名人经历硬套在用户身上。
7. 回到用户价值排序：不问“哪个人最成功”，而问“哪个结果你最不能接受”“你愿意付什么代价”“什么条件一变，你的选择就会变化”。

**[表 10]**

| 产品行为准则 不以“成功人物”作为答案；不把结果倒推成正确决策；不把历史人物神化；不把相似案例包装成预测。 |


## 6. 数据模型：人生决策事件（Decision Episode）

真正的数据单位不是“人物”，也不是“一本传记”，而是“某个人在某个阶段面对一次具体决策时的一段可还原语境”。一个人物一生可以拆成很多个 Decision Episode。

**[表 11]**

| 字段组 | 建议字段 | 意义 |
| 人物与时间 | person_id, name, age, year, stage | 定位这个事件发生在人生哪个阶段 |
| 来时路 | prior_path, prior_commitment, prior_failures | 在做当前选择前，他已经经历了什么 |
| 困境 | dilemma, options, trigger | 究竟在纠结什么，为什么此刻必须选 |
| 现实条件 | constraints, resources, family, money, location | 决定案例是否真正可比 |
| 内在变量 | motivation, values, confidence, uncertainty | 解释为什么同样外部条件会有不同选择 |
| 实际选择 | choice, actions, reversibility | 真实做了什么，而不是后人总结 |
| 后果 | short_outcome, mid_outcome, long_outcome | 至少分短/中/长期，不用“成功失败”二元化 |
| 后续分叉 | next_episode_ids | 人生不是一次选择后结束 |
| 反思 | self_reflection, later_comment | 本人后来如何评价那次选择 |
| 证据 | sources, quotes, evidence_level | 每个关键结论能追溯到哪里 |
| 不确定性 | unknowns, disputed_claims | 明确哪些内容不能确定 |
| 匹配标签 | themes, mechanisms, constraints_vector | 用于召回、筛选与重排 |

核心思想：所谓“和我像”，不能只看一句文本的语义相似，而要看“之前的路径 + 当前的冲突 + 现实约束 + 可选道路 + 心理目标”是否结构上相似。

## 7. 技术路线：48 小时 MVP 与正式版本


### 7.1 48 小时 MVP：不要过度工程


**[表 12]**

| 层 | 推荐方案 | 理由 |
| 前端 | Next.js / React + Tailwind | 最快搭建流程与分叉地图，生态成熟 |
| 后端 | FastAPI 或 Next.js API Routes | 团队如果 Python 熟就 FastAPI；纯前端队可直接 Next.js |
| LLM | 一个可靠的通用模型 API | 负责结构化、重写、解释、反类比，不训练模型 |
| Embedding | 通用中文/多语 embedding API | 支持用户困境与案例的语义召回 |
| 向量库 | Chroma / pgvector / Supabase Vector | 数据量只有几十到几百条，不需要复杂集群 |
| 结构化存储 | SQLite / Postgres / JSON | 保存 Decision Episode 元数据与来源 |
| 检索 | Dense + metadata filter；时间够再加 BM25 | MVP 先保证结构正确，再追求召回 sophistication |
| 重排 | LLM rerank 或简单加权打分 | 把“语义像”升级成“结构像” |
| 可视化 | SVG/Canvas/React Flow 可选 | 展示人生分叉，提升 Demo 记忆点 |


### 7.2 正式版本：从 RAG 走向 Experience Graph

正式产品建议形成“事件图谱 + 向量索引 + 证据存储”的混合架构。人物是节点，人生阶段是节点，Decision Episode 是核心事件节点，事件之间通过“后续分叉”“主题相似”“约束相似”“结果相似/相反”等边连接。
Hybrid Retrieval：BM25/关键词 + embedding + 元数据筛选。
Rerank：Cross-Encoder 或 LLM judge，重点评价“情境结构相似度”而不只是文本相似度。
Diversity Selector：确保返回案例在“选择方向”上有差异，而不是三个都在说同一件事。
Evidence Provenance：所有关键事实绑定 source_id 与证据片段。
Counter-Analogy Generator：专门输出“不应该照搬的原因”。
Experience Graph：让用户可以沿着一个人的后续节点继续展开，也可以在相似节点横向跳到其他人。

## 8. 检索与匹配算法设计

技术上最重要的不是“相似度 87%”，而是让相似度可解释。建议将总匹配分拆为几个有意义的维度。

**[表 13]**

| 匹配维度 | 含义 | MVP 实现 |
| 阶段相似 | 年龄/教育/职业阶段是否接近 | metadata filter |
| 来时路相似 | 之前投入、失败、转换次数等是否接近 | LLM 结构化 + embedding |
| 困境结构相似 | 是否同属“坚持/转向”“稳定/冒险”等 | 标签 + embedding |
| 约束相似 | 时间、经济、家庭、地域、身份压力 | 结构字段加权 |
| 目标相似 | 用户真正想要的是兴趣、收益、影响力还是稳定 | LLM 抽取 + 标签 |
| 可逆性相似 | 选择能否撤回、试错成本多大 | 规则字段 |
| 差异惩罚 | 时代、制度、资源等结构差异太大时降权 | Counter-analogy score |

可解释展示建议不要直接给“86% 像你”，而是给维度卡：阶段高相似、沉没成本高相似、经济条件低相似、家庭约束未知、时代背景显著不同。这样既更可信，也自然引出“为什么不能照搬”。

**[表 14]**

| 推荐的召回策略 先用 embedding 召回 10–20 个候选 → 用 metadata 排除明显不匹配 → LLM/规则重排 → 按“不同选择”做多样性采样 → 选 3 个最终案例。 |


## 9. 数据来源、可信度与冷启动

历史数据的价值不是“古代更智慧”，而是公开、可引用、很多关键人物已经有完整传记、日记、书信与后人研究，适合作为第一批高质量案例。长期产品不应限制在历史人物。

**[表 15]**

| 来源类型 | 优点 | 风险 | 适合用途 |
| 本人日记/书信/自传 | 最接近当事人视角 | 仍可能自我包装、版本问题 | 动机、反思、当时认知 |
| 权威传记/学术研究 | 结构完整、可交叉核验 | 作者解释框架会影响叙述 | 背景、时间线、因果脉络 |
| 公开演讲/访谈 | 现代人物真实表达丰富 | 媒体叙事与表演性 | 近现代/当代案例 |
| 可靠百科/公共数据库 | 冷启动快、信息标准化 | 细节与内心不足 | 基础元数据 |
| 普通真实用户投稿 | 贴近目标用户 | 真实性、隐私、选择性叙述 | 后续扩展校园/职业案例 |

MVP 数据规模建议：10–20 位人物、36–60 个高质量 Decision Episode。宁可 40 条非常完整、有来源、分叉清晰的案例，也不要 1000 条自动切碎的传记片段。
案例选择策略：不要只选成功者。每个主题都尽量覆盖“坚持得到回报”“坚持但长期受损”“转向后找到新路”“转向后发现并不适合”“先试探再转向”等不同结果，避免幸存者偏差。

## 10. 页面与交互设计

UI 不建议以聊天框为主。聊天框会让评委一眼把它理解成“又一个 AI Chat”。更合适的是“路口 + 分叉 + 案例卡 + 证据抽屉”的地图式体验。

**[表 16]**

| 页面 | 核心内容 | 必须展示的技术/产品信息 |
| P1 来时路 | 5–10 个快速问题 / 自然语言经历 | 收集 prior path、目标、约束 |
| P2 当前路口 | AI 抽取的核心冲突、选项、约束 | 让用户修改，体现可控性 |
| P3 人生分叉地图 | 3 条相似人生路径 | 不同选择 + 结果，不是排名 |
| P4 案例详情 | 当时处境→选择→结果链→后来反思 | 证据、来源、未知 |
| P5 像与不像 | 解释为什么可参考/不可照搬 | Counter-Analogy 核心亮点 |
| P6 回到自己 | 最不能接受的结果/愿意付的代价/下一步行动 | 把洞察转化为自我决策，而不是 AI 决策 |


**[表 17]**

| 视觉核心 过去是已发生的线，现在是一个节点，未来是迷雾；系统做的不是替你画未来，而是把“别人从相似节点出发后已经走完的路”叠加给你看。 |


## 11. 48 小时 MVP 具体做什么

比赛阶段最危险的是“因为概念大，所以功能也做大”。建议只做一条非常顺的端到端链路。

**[表 18]**

| 优先级 | 必须做 | 原因 |
| P0 | 用户画像 + 当前困境结构化 | 没有这一层就只是普通搜索 |
| P0 | 36–60 条人工校验的 Decision Episode | 这是 Demo 的核心资产 |
| P0 | 三案例检索 + 多分叉选择 | 展示核心产品机制 |
| P0 | 来源 + “像/不像”解释 | 这是可信度与创新性的关键 |
| P0 | 人生分叉地图 | 让抽象概念一眼可见 |
| P1 | 一个 What-if 条件调整 | 加分项：条件变化→匹配变化 |
| P1 | 事件详情的后续节点展开 | 让“人生是路径”而不是单点 |
| P2 | 账号、社区、语音、数字人、多 Agent | 比赛期间坚决不做 |

第一批只支持 6–8 类问题：坚持还是放弃、探索还是专注、稳定还是冒险、换方向还是继续、短期收益还是长期兴趣、离开还是留下、失败后是否重来、家庭期待与个人选择。

## 12. Demo 剧本：以“要不要转专业”为例

这个 Demo 要让评委在 90 秒内看懂“你们不是 ChatGPT + 历史人物壳”。
1. 用户输入：“我已经学了这个专业两年，但越来越觉得不适合自己。我对另一个方向很感兴趣，但现在换是不是太晚？”
2. 系统追问 5 个关键信息：已投入时间、新方向验证程度、是否允许延毕/补课、家庭/经济约束、你最看重兴趣/稳定/收入/成长中的什么。
3. 系统生成“当前路口卡”：核心冲突=坚持 vs 转向；沉没成本=中高；新方向确定性=中；可逆性=中；最关注=长期兴趣与成长。用户可手动修改。
4. 地图出现三条路径：A“继续原方向”、B“直接转向”、C“先低成本验证再转向”。每条路径对应一个真实案例。
5. 点击案例后，不是人物语录，而是：当时背景、他知道什么、有哪些选项、实际选择、1–3 年结果、长期结果、后来反思。
6. 系统显示“为什么像你 / 为什么不像你”：例如同样存在沉没成本，但对方没有你的经济约束；对方的新方向已经验证两年，而你只了解两个月。
7. 最后问用户：“哪一种结果你最不能接受？”“如果先用一个学期做低成本验证，你的选择会变化吗？”并生成一个具体的下一步验证行动。

**[表 19]**

| Demo 结尾句 “历史没有替你做选择，但现在你已经知道：哪些路真的有人走过，它们分别付出了什么。” |


## 13. 技术质量与评估体系

要避免被评委理解成“Prompt + 向量库”，就必须把检索过程、证据与评估做出来。

**[表 20]**

| 指标 | 定义 | MVP 验证方法 |
| Retrieval Relevance | 案例是否真的与用户处境相关 | 准备 15–20 个问题，人工标注可接受案例 |
| Structural Match | 阶段、冲突、约束是否匹配 | 人工对 5 个维度打分 |
| Evidence Coverage | 关键事实是否能追溯到来源 | 抽查事实是否都有 source_id |
| Faithfulness | 生成解释有没有超出材料 | 人工/LLM judge 对照证据 |
| Diversity | 三个案例是否提供不同选择 | 规则检查 choice_type 不重复 |
| Counter-Analogy Quality | 是否指出关键不可比因素 | 人工评分：是否具体、是否重要 |
| Insight Gain | 用户是否获得原先没想到的视角 | Demo 后 1 题：是否发现新的约束/结果 |
| Decision Agency | 系统是否替用户给结论 | 检查最终文案无“你应该”式决定 |

可视化技术细节建议：在“为什么匹配到这个案例”中展示候选召回、结构标签、相似维度与证据引用，而不是隐藏所有过程。黑客松评委会更容易看到技术深度。

## 14. 创新性与竞品定位

创新性不能讲“我们做了历史人物聊天”或“我们用了 RAG”。相邻项目已经覆盖这些方向：历史人物学习与对话、多人物 Council、基于人物著作的 RAG、以及“现代事件→历史事件”的类比检索。

**[表 21]**

| 方向 | 已有产品/研究常见能力 | 我们保留的差异 |
| 历史人物聊天 | 先选人物，再模拟他说什么 | 先输入自己的处境，再找真正经历过相似路口的人 |
| Persona RAG | 用人物著作/语录让回答更像他 | 不是“说得像”，而是“做过什么、结果如何” |
| 多人物 Council | 让多个思想家讨论同一个问题 | 不让人物模拟给建议，直接比较真实决策事件 |
| 历史类比研究 | 现代事件→历史事件相似 | 个人人生困境→人生决策事件；还加入结果链与反类比 |
| MBTI/职业测评 | 给用户类型/倾向 | 给用户动态处境与相似路径，不做稳定标签 |

此前检索到的相邻案例包括：Agora Cosmica（历史人物学习/对话/Council）、RAGTalk（历史人物 Persona RAG）、Past Meets Present / Historical Analogy of LLMs（历史类比检索研究）。这些说明“历史人物聊天”和“历史类比”本身不是空白；我们应诚实把创新讲成“处境检索 + 人生决策事件 + 多分叉结果 + 反类比 + 证据层”的组合机制。

**[表 22]**

| 最该守住的核心创新 检索单位不是“人物”，而是“一个人在某个时间段的一次人生决策事件”；返回结果不是“一个答案”，而是“多个不同选择的真实后果分叉”。 |


## 15. 商业价值、频次问题与变现路径

团队已经识别到最关键的问题：人生重大决策天然低频。如果强行做成“每月订阅的人生导师”，很可能商业逻辑不成立。解决方式不是假装它高频，而是把价值从“每天用”转成“在关键场景高价值 + 在教育场景高复用 + 数据/能力可被其他平台调用”。

**[表 23]**

| 模式 | 客户/用户 | 卖什么 | 优点 | 主要问题 |
| B2C 免费/轻付费 | 大学生/职业早期 | 高级案例、深度路径、报告 | 验证需求、传播快 | 低频、付费意愿不确定 |
| 高校 B2B2C | 生涯中心/通识/新生教育 | 案例库 + 课堂工具 + 管理端 | 稳定场景、重复使用 | 销售周期长 |
| 咨询工具 | 生涯/职业咨询师 | 案例检索、访谈辅助、报告 | 专业用户高价值 | 需要可信度与合规 |
| 内容/出版社合作 | 传记、博物馆、教育内容机构 | 把内容结构化成可交互经验 | 内容方已有资产 | 合作复杂 |
| Experience API | 教育/AI/咨询平台 | 经验事件检索与匹配 API | 可规模化、数据壁垒明显 | 必须先积累数据资产 |

比赛阶段不需要硬凑付费闭环。最可信的商业叙事是：先用 C 端学生验证“用户是否愿意花几分钟输入自己，并认为相似案例能带来新视角”；如果成立，再进入高校生涯教育与通识课程，长期积累成经验数据库与匹配 API。

**[表 24]**

| 商业资产真正是什么 不是聊天 UI，也不是某个大模型，而是高质量、可引用、可比较的 Decision Episode 数据资产，以及把“人 → 处境 → 相似经验”匹配起来的引擎。 |


## 16. Echo 赛题契合度与答辩叙事

这个项目和 Echo 的最佳契合点，不是“用了 AI”，而是对“教育应该如何对待下一个像你一样的人”给出一个具体回答：教育不应该只讲结论和大道理，而应该把前人真实经历过的选择、犹豫、失败、转向和代价变成后来者可访问的经验。

**[表 25]**

| 主题回答 我们希望教育不只告诉下一个像我们一样的人“应该怎么做”，而是把前人真的怎么走过、为什么这样走、后来发生了什么，交给他自己判断。 |

团队讨论里反复出现一个非常有力量的观点：“很多大道理需要阅历才能解压。”这可以成为 Pitch 的哲学底层：语言很压缩，经验很昂贵；我们的产品尝试让人不用亲自经历所有代价，也能通过真实案例把那些被压缩成一句话的道理重新展开。
因此，Echo 不只是“回响历史人物的声音”，而是“让前人的来路，在后来者站到相似路口时重新产生回响”。

## 17. 风险、边界与产品伦理


**[表 26]**

| 风险 | 表现 | 产品缓解 |
| 历史类比误导 | 表面像，结构其实不同 | 强制 Counter-Analogy；展示差异维度 |
| 幸存者偏差 | 只选成功名人 | 数据集必须覆盖失败、转向、长期代价 |
| 结果论 | 因为后来成功就认为当时决策正确 | 还原“当时知道什么”，避免上帝视角 |
| 人物神化 | 把名人当权威答案 | 系统不输出人物建议，只输出真实事件 |
| 幻觉 | AI 补全心理活动 | 事实、解释、未知分层；证据绑定 |
| 隐私 | 未来用户真实经历被泄露 | 用户案例匿名化、授权、最小化存储 |
| 心理依赖 | 用户把系统当人生决策器 | 明确不预测，不给“最佳选择”；强化用户自主决定 |
| 敏感领域误用 | 高风险政治/医疗/法律决策 | 限制场景，明确仅为经验参考，不作为专业决策依据 |


## 18. 团队分工与开发节奏

假设 4 人、48 小时，建议按“产品/数据/后端检索/前端 Demo”并行，而不是多人同时改一个模块。

**[表 27]**

| 角色 | 前 12 小时 | 12–30 小时 | 30–48 小时 |

## 附录 B. 示例 Prompt / 结构化输出协议

MVP 里最值得标准化的不是“人物角色 Prompt”，而是三个结构化环节：Situation Parser、Episode Reranker、Counter-Analogy。

**[表 31]**

| 模块 | 输入 | 输出要求 |
| Situation Parser | 用户来时路 + 当前问题 | 只输出 JSON：stage、dilemma、options、constraints、goals、risk、reversibility、unknowns |
| Episode Reranker | 用户 Decision State + 候选事件 | 逐项给结构匹配理由，不允许引用候选外事实 |
| Counter-Analogy | 用户与最终案例 | 至少 2 个重要不可比因素；若证据不足，明确 unknown |
| Evidence Writer | 案例结构 + source snippets | 将“史实/本人表述/后人解释/AI 类比/未知”分层输出 |

生成阶段原则：模型只能在“解释”和“重组”层发挥，不允许把没有证据的心理动机写成事实。

## 附录 C. Demo 验收清单

□ 用户输入一个问题后，30 秒内能看到“当前路口”的结构化结果。
□ 用户可以手动修改 AI 对自己处境的理解。
□ 返回至少 3 个案例，且至少覆盖 2 种不同选择方向。
□ 每个案例都能看到短/中/长期结果，不只是“成功/失败”。
□ 每个案例都有“为什么像你”和“为什么不像你”。
□ 至少一个关键事实可以点开看到证据来源。
□ 系统明确标记“未知/有争议”的内容。
□ 最终页面不出现“你应该选择 X”这样的结论。
□ 页面上能一眼看到人生分叉地图，而不是只有聊天记录。
□ 断网/API 错误时有缓存的 Demo 数据，保证上台可演示。
□ 3–5 分钟 Pitch 能完整讲完：痛点 → 机制 → 技术 → Demo → 价值 → 主题。
