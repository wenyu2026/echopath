## 0. 三十秒看懂这是什么

**一个「人群轨迹 → 个性化决策地形」引擎。**

```
用户说几句话
    ↓
① 对话访谈：AI 一问一答，边聊边抽结构（动态追问，不是固定问卷）
    ↓
② 去数据库找「来时路相近的人」
    ↓
③ 告诉他：像他这样的人真实走过哪几条路，每条路的代价是什么
```

**历史名人只是演示数据。** 真实产品是给学校装校友数据、给公司装员工数据 ——
**引擎不变，只换数据源**（这一条有自动化验证，见 §5）。

## 4. API

### 4.1 对话访谈

```
POST /api/interview/start
  → { state, message, asked_field, progress }

POST /api/interview/answer
  body: { state, answer, asked_field }
  → { state, extracted:{updates,memorable_quote}, message|null,
      asked_field, done, stop_reason, progress }

POST /api/interview/finish
  body: { state }
  → { state, summary, elapsed_ms }
```

**⚠️ 无状态设计**：整个中断状态由**前端持有**并每次带回来。
- 好处：后端不用建会话存储；用户刷新能续上；调试时请求里能直接看到状态
- 代价：state 随每次请求传，稍大（约 1-2KB）

### 4.2 决策地形

```
GET  /api/sources    → { sources: [{id, label}] }

POST /api/landscape
  body: { situation: SituationV2, user_quote?, source_id? }
  → LandscapeResponse（见 src/types/landscape.ts）
```

**⚠️ `situation.root_factors` 可以是空数组** —— 后端会用 LLM 从自然语言推。
（访谈采到的是「家人希望稳定就业，不支持折腾」，根因素是封闭词表里的「家庭约束」，
两者之间的映射不是词面关系，关键词表列不全。）

### 4.3 案例详情

```
POST /api/case
  body: { episode_id, source_id?, ...用户处境（反类比要用） }
  → { episode, temporal_boundary, evidence_layers, evidence_detail, why_different }
```

## 5. 改代码前必须知道的 8 条设计约束

**这些不是风格偏好，是实测得出的结论。推翻任何一条都会让结果变假。**

### ① `choice.type` 和「决策机制」是两回事，不能互相替代

```
choice.type  记「做了什么」    ← 客观行为
archetype    记「在权衡什么」  ← 决策结构
```

实测：把 `choice.type` 当标准答案喂给模型，36 条里改了 16 条。
但检查机制描述后确认**模型更准**：

| 案例 | 库里标注 | 模型判定 | 史实 |
|---|---|---|---|
| 鲁迅 | 直接转向 | **双轨** | 退学后仍持续翻译写作 |
| 乔布斯 | 放弃 | **双轨** | 退学但继续旁听 |

→ `archetype` 是**新增字段**，不覆盖 `choice.type`。

### ② 路径聚类必须用 `root_factors` 的集合重叠，**不能用机制文本的 embedding**

实测三条机制文本：

```
鲁迅: 当已投入的路径与制度绑定的身份同时构成约束时…
李安: 当已有投入形成特定能力积累，但制度性通道长期不开放时…
村上: 当既有路径尚能维持生存且未彻底失效时…
```

**字符重叠高达 0.76–1.00（完全区分不开）**；而 `root_factors` 的 Jaccard 是 0.25–0.67。

### ③ 聚类**不能用一个全局阈值**同时管「与用户像」和「成员彼此像」

实测 Jaccard 分布是**断崖式**的，没有中间地带：

```
0.60 ← 10 条案例
0.33 ← 10 条案例     ← 阈值放中间 = 4 条路里 3 条只有 1 个案例
```

`abandon`/`persist` 这类走法，成员彼此很像，但与「用户」重叠天然就低。

→ 现在：**先按 archetype 分组，组内用「共识根因素」做连贯性检查**；
与用户的重叠**只用于排序，不用于准入**。

### ④ 「代价」≠「结果链」

踩过两次：
1. 直接拿 `outcomes.mid_term` → 输出「后来获得跟随 X 进行博士研究的机会」（**收获**不是代价）
2. 只按「负面词」过滤 → 「未知：本来源没有证明…」里的「没有」被判成负面，照样漏进来

→ 现在：先挡数据维护备注（`isMetaNote`），再找**明确负面**的结果。

### ⑤ 「问了 ≠ 答了」

实测：问了 `goals`「你图它什么」，用户答的却是 `fear`。
抽取器只抽用户真说了的 → goals 空着，但系统记成「已问过」，**再也不问了**。

→ 允许重问一次（换角度 + 打折 ×0.6）。见 `INTERVIEW_CONFIG.max_asks_per_field`。

### ⑥ 数据里混着「数据维护备注」（19%）

`data/episodes.json` 的 `outcomes` 里，**21/108 条不是人物结果**：

```
「未知：本来源没有证明所有受影响员工实际获得安置。」
「未知：所用大学简介未列中断后最初数年的个人收入与学业影响。」
```

这些备注**本身是好东西**（诚实标注查不到什么），但**不该在 `outcomes` 里**。

→ 引擎有 `isMetaNote()` 挡着（治标）。
→ **根本修法：把它们挪到 `reflection.unknowns`。这是数据层的活，还没做。**

### ⑦ 「时间边界」必须视觉上分开

```
当时已经知道什么     ← 他做决定时掌握的信息
实际做了什么
后来发生了什么       ← ⚠️ 这些发生在他做决定之后
```

合起来写就会变成「因为他选了 A，所以后来成功了」——
**那是成功学，不是决策参考。** 数据规范里叫 Temporal Information Boundary。

### ⑧ 只有 1/4 条路径能挂上用户原话 —— 这是**刻意**的

代价要挂用户原话（「↳ 因为你刚才说…」）才有说服力。
但**挂的前提是语义真的相关**，不相关就不挂。

试过放宽兜底，结果输出变成：

```
★【挂你原话】 仍继续学习，1969 年取得文凭。      ← 这是进展不是代价
```

**否决了。** 代价栏里写进展比不写更糟 —— 用户会以为系统分不清好坏。

> 附带：判断「是否相关」**不能用字符重叠**。
> 「我不太怕晚毕业，最怕再浪费几年」vs「第一次跨考落榜」字面重叠 0.029，
> 但语义明显相关（都是「白走一趟」）。现在用**概念命中**。

## 8. ⚠️ 上生产前必须处理的事

### 8.1 隐私红线（最重要）

现在装的是历史名人数据，**没有隐私问题**。但换成学校/公司的真实数据后，性质完全变了：

> **最危险的不是技术泄露，是「用途漂移」：**
> 你给学生做「发展方向匹配」，学校会不会拿它去考核就业率？
> 你给员工做「发展路径匹配」，公司会不会拿它去决定裁谁？

**必须写死的规则**：

```
数据只能用于给当事人自己提供参考。
不得用于对该当事人的评价、考核、筛选、淘汰或任何处置决定。
机构不得查看个体作答内容，只能看到聚合统计。
```

`privacy_level` 和 `source_type` 字段已经带上了（`src/types/landscape.ts`），
但**隔离逻辑没有实现** —— 现在是单租户 Demo。

### 8.2 无状态设计的代价

`/api/interview/answer` 让前端把整个 state 传回来。Demo 没问题，
但**这等于信任客户端** —— 上生产要改成服务端会话。

### 8.3 无鉴权 / 无限流

任何能访问 3000 端口的人都能调 LLM（花你的额度）。

## 9. 一句话记住这个产品的边界

```
✅ 做：把别人走过的路摊开，告诉他每条路的代价
❌ 不做：预测未来、算成功率、告诉他该选哪条
```

`data/README.md` 里有一句原文，值得贴在墙上：

> 数据样本偏向公开资料充分的知名人物，**不能用于计算成功率或最优人生**。
