## 4. 数据与接口要求

严格使用工作包第 3 节中的 PersonCard / RetrievalView v0.1 和十维字段约定。该文档是实现起点；A 正式化公共类型和共同样例后，必须与它对齐再扩六张。

PersonCard 是完整档案，RetrievalView 是按决策节点导出的**决策前**数据。不要让在线系统读取自然语言长传记自行理解。

来源、原子事实、状态快照、决策事件、机制各有稳定 ID。正式事件只引用现有 episode_id；新事件先作为候选，不直接改写主库。

每个维度保留值、原文、信息性质、引用、支持程度、时间和未知原因。未知 value=null，不能填默认中等。分档标签属于建模，不能因来源真实就把“经济压力 high”自动标为史实。回顾性解释不能参与过去状态的匹配。

archetype 与 root_factors 复用现有类型词表；choice.type 和机制分开，不能相互覆盖。你只导出特征、证据和覆盖情况，不计算用户相关排名。

## 5. 按这个顺序实现

**阶段一：审计和单卡。**

列出正式人物候选、对应事件、场景、来源和缺口。从定位充分的一个人物开始，完成来源→事实→时间线→决策前状态→机制→检索视图。先提供文件和校验结果给 A 验证能读取；接口有差异时先修约定，不批量复制错误。

**阶段二：制作流水线。**

拆成可重跑阶段：来源登记、原文片段输入、事实抽取、时间线整理、事件采样、状态构建、决策/结果分层、机制标注、验证、导出。每步保存输入摘要、输出、提示词版本、运行状态、错误和待确认项。

固定输入/版本重复执行产生稳定 ID 和相同确定性导出。模型抽取结果作为版本化中间产物保留，不能宣称模型重跑必然逐字相同；重建导出时复用已保存的中间产物。检查点使用临时文件写完后替换，失败不把半成品标成完成。

提供提示词模板及无密钥的人工录入/已有事实导入方式，使校验和导出可以全离线运行。若接入在线抽取，复用仓库网关配置，不在新脚本硬编码 key 或另建不一致的网关实现。

**阶段三：扩展六张。**

优先扩场景和走法覆盖，保留真实代价、未知与制度差异。每新增一张先过校验，再进入试验 manifest。人工审查清单逐项列关键事实和匹配维度，不能由 AI 代签。

**阶段四：对照与交接。**

有 S1 材料时整理 1–2 张单独对照；没有则记录缺口。给 A 提供每场景可参考事件、关键差异和不能据此推断的内容，参与十八个固定情景的预期标注。最终提交运行说明、测试、限制和下一步。

## 6. 采样和证据纪律

人生状态按事件采样，不按每一年凑快照：路径变化、投入/经济/责任/资源变化、新方向验证、外部冲击、明确期限。

事实必须绑定具体版本/章节/页码/段落或等效精确定位。搜索页、整本书链接、来源标题只能作为线索，不能独自证明具体字段。来源冲突保留争议，不强行统一。

构建某节点状态时只使用当时已经发生且时间顺序可证明的事实；同年事件没有顺序证据则不默认早于决策。未来奖项和后来成败不得用于过去状态，心理动机缺依据则标 inference 或 unknown。

后世传记可以支持早年客观事实，资料出版晚不是自动排除理由；事件发生时间和资料形成时间分开记录。不得把人物后来对自己的解释当成当时已经知道的事实。

原本 S1 的 temporal_boundary_checked=True 和 audit.pass 不是实际验证证据。新版每次生成可复核的时间检查结果，不复用硬编码“已通过”。

## 7. 测试与验收

至少实现以下正反例；测试素材标 synthetic，不混入正式人物：

- 合法单卡可以导出，版本/ID/引用闭合；悬空引用和重复 ID 拒绝。
- 没有证据的维度保持 null；推断不能冒充事实，retrospective 不进入匹配视图。
- 注入明确晚于决策的事实，校验失败；同年顺序不清的事实不通过时间门槛。
- 只改未来结果或声望，导出的决策前视图不变。
- 后来发表的可靠资料若支持早年事实，不因出版晚被错误排除。
- 重复导出一致，中断检查点可恢复；失败输出不进入可用 manifest。
- 机器检查通过但没有真人审查的卡仍为 pending。
- 三个场景覆盖和 partial 缺口有明确报告，不以文件数代替质量。

离线数据模块不依赖演示 key。npm test、node --test data/validate-data.test.mjs、npm run validate:data、npm run build 是仓库已有命令；新增脚本必须在交接里给出实际可复制的命令。npm run preflight 的在线部分、完整浏览器演示由 A 集成时执行。不要把没跑过的检查写成 PASS。
