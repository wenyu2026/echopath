# Demo 剧本与 Pitch 骨架

> 目标：让评委在 **90 秒内**看懂「这不是 ChatGPT + 历史人物壳」。
> 最后更新：2026-10-02

---

## 一、Demo 主线：要不要转专业

**为什么选这个**：方案已有完整雏形，大学生共鸣最强，且能覆盖「坚持 / 转向 / 先验证再转向」三种路径。

### 90 秒逐拍脚本

| 时间 | 屏幕 | 旁白（说什么） |
|---|---|---|
| **0–10s** | 输入框 | 「这是每个大学生都可能遇到的一刻：学了两年，越来越觉得不适合自己。」 |
| **10–20s** | 用户输入困境 | 输入：「我已经学了这个专业两年，但越来越觉得不适合自己。我对另一个方向很感兴趣，但现在换是不是太晚？」 |
| **20–30s** | 系统追问 5 问 | 「它没有立刻给建议 —— 而是先问清五件事。」<br>①已投入时间 ②新方向验证程度 ③是否允许延毕 ④家庭/经济约束 ⑤最看重兴趣/稳定/收入/成长中的什么 |
| **30–45s** | **当前路口卡** | 「它把你的处境结构化了 —— 不是关键词，是结构。」<br>核心冲突=坚持 vs 转向；沉没成本=中高；可逆性=中；最关注=长期兴趣<br>**现场改一个字段**，证明用户可控 |
| **45–60s** | **人生分叉地图** | 「关键在这里 —— 它不给你一条路，给你**三条真实有人走过的路**。」<br>A 继续原方向 / B 直接转向 / C 先低成本验证再转向 |
| **60–75s** | 点开案例 B | 「点开不是名人语录，是完整的结果链：当时知道什么 → 有哪些选项 → 实际选了什么 → 1-3 年结果 → 长期结果 → 后来怎么反思。」<br>**点开证据抽屉**：这个事实来自哪里 |
| **75–85s** | **像与不像** | 「最关键的一屏：**为什么像你，以及为什么你**不能照搬**。**」<br>「同样有沉没成本，但对方没有你的经济约束；对方的新方向已验证两年，你只了解两个月。」 |
| **85–90s** | 回到自己 | 「最后它不替你决定，只问你一个问题：**哪一种结果你最不能接受？**」 |

### 收尾句（方案已定，照用）

> **历史没有替你做选择，但现在你已经知道：哪些路真的有人走过，它们分别付出了什么。**

## 二、🔴 三个必须现场演示的「技术证明」

**光讲没用，必须让评委看见。**

### 证明 1：What-if 条件调整（性价比最高）

**现场改一个条件，看结果实时变化。**

> 「假设我不怕延毕，匹配结果会变吗？」

**为什么这是杀手锏**：它**证明了这是结构匹配，不是文本匹配**。
文本相似度不会因为「假设我不怕延毕」而改变。**这是无法反驳的技术展示。**

**必须有**：改条件 → 匹配的案例和维度分数变化 → 可视化对比。

### 证明 2：维度卡（不要写「相似度 87%」）

```
阶段相似      ████████░░  高
来时路相似    ███████░░░  高
困境结构      █████████░  高
约束条件      ███░░░░░░░  低
目标相似      ████████░░  高
可逆性        ██████░░░░  中
⚠️ 差异惩罚    █████████░  时代背景显著不同
```

**最后一行自然引出「为什么不能照搬」。**

### 证明 3：检索过程可视化

在「为什么匹配到这条」里展示：

```
候选召回 47 条 → 元数据过滤后 18 条 → 结构重排后 6 条 → 多样性采样 3 条
耗时 4.2s
```

**方案第 13 节原话**：「而不是隐藏所有过程。黑客松评委会更容易看到技术深度。」

## 三、必须现场说的三句话（防质疑）

| 评委可能问 | 你回答 |
|---|---|
| 「这不就是 ChatGPT 吗？」 | 「ChatGPT 检索的是**知识**，我们检索的是**决策事件**。而且它会主动告诉你**为什么不能照搬** —— 聊天机器人不会做这件事。」 |
| 「历史人物和现在不一样，参考价值在哪？」 | 「**这正是我们的核心机制。** 我们不假装可比，而是强制输出差异维度。你看这一屏 —— 时代背景的差异惩罚是满格。」 |
| 「这有商业价值吗？低频吧？」 | 「**对，我们不假装它高频。** C 端重大决策天然低频。真正的场景是高校生涯教育 —— 把案例库变成课堂工具。这既高频复用，又扣住 Echo 赛题。」 |

## 四、Pitch 骨架（3–5 分钟）

### 结构

```
1. 痛点（30s）
   语言很压缩，经验很昂贵。
   很多大道理需要阅历才能解压。

2. 洞察（30s）
   迷茫的人不缺建议，缺的是「和我像的人后来怎么样了」。
   但经验散落在传记、书信、访谈里 —— 不可检索、不可比较、不可代入。

3. 机制（60s）
   检索单位是「决策事件」，不是「人物」。
   结构化匹配 7 个维度，不是文本相似。
   强制反类比 + 证据分层 + 多分叉。

4. Demo（90s）
   走一遍上面的脚本。

5. 技术（30s）
   7 维度结构匹配 / 证据溯源 / 多样性选择
   实测：结构化 6 秒内完成

6. 价值与主题（30s）
   商业：高校生涯教育 + 经验 API
   主题：教育不该只告诉后来者「应该怎么做」，
        而应该让他们看见前人真的怎样做过、付出了什么代价。
```

### 一句话定位（背下来）

> **不是预测你的未来，而是把别人已经走过的未来提前给你看。**

### 主题回答（答辩收尾用）

> 我们希望教育不只告诉下一个像我们一样的人「应该怎么做」，
> 而是把前人真的怎么走过、为什么这样走、后来发生了什么，交给他自己判断。

## 五、⚠️ 上台前的硬检查（逐项打勾）

```
□ 一条命令启动全部（前端 + 后端）
□ 输入问题后 30 秒内出现「当前路口」结构化结果
□ Situation 可以手动修改
□ 返回 3 个案例，且至少覆盖 2 种不同选择方向
□ 每个案例能看到短/中/长期结果
□ 每个案例有「为什么像你」和「为什么不像你」
□ 至少一个关键事实能点开看到证据来源
□ 明确标记「未知/有争议」的内容
□ 最终页面不出现「你应该选择 X」
□ 页面上能一眼看到人生分叉地图，不是只有聊天记录
□ 🔴 断网/API 错误时有缓存数据 —— 保证上台可演示
□ 3–5 分钟 Pitch 能完整讲完
```

**最后一项最重要**：演示前**主动拔网线测一次**。

## 六、如果时间不够（降级方案）

**保留**（缺了就不成立）：
1. 处境结构化
2. 3 个案例 + 多分叉
3. 反类比（为什么不像你）
4. 分叉地图

**可以砍**：
- What-if 条件调整
- 检索过程可视化
- P6 回到自己页

**绝对不能砍反类比** —— 那是这个产品区别于聊天机器人的**唯一铁证**。
