## 文件与复核入口

| 文件 | 内容 |
|---|---|
| `episodes.json` | 消费端使用的事件、事实证据及 AI 建模标注 |
| `sources.json` | 来源 ID、题名、发布者、URL、正文定位、访问方式和局限 |
| `review.json` | 每个事实字段绑定的来源组、未知字段、Demo 类比边界、负面类型与人类审查状态 |
| `validate-data.test.mjs` | 校验器的拒绝错误数据测试 |

阅读某条事件时，从 `evidence.claim` 与 URL 查看支持的具体主张，再按 `sources.locator` 定位正文。`review.field_sources` 使用点路径，数组以数字索引定位；一个字段的多个来源是共同支持该字段的资料组，不表示每个来源独立支持整段。建模字段不得通过这一机制冒充史实。

## 事实、本人表述与建模

- `prior_path`、实际行动、带来源的结果是公开资料中的事实或带归属的本人回顾。`self_writing`、`interview` 不等于独立证实；不把回忆写成当时的现场记录。
- `decision_state` 全部字段、`choice.type`、阶段及检索标签是 AI 为匹配整理的分类。`evidence` 中单列 `ai_inference`，并在 `unknowns` 说明。未发生选项不代表本人真实考虑过，风险等级也不是量化测量。
- 未查到的本人评价直接省略；没有完整资料的结果以“未知：”开头，并同步记入 `reflection.unknowns` 和复核索引。不用后来的获奖倒推当时知道什么。
- 短、中、长期表示事件后的相对观察顺序，不规定统一的 1/3/10 年窗口；尽可能写明日期。某些人的观察因来源截止或去世而终止，不虚构后续结果。
- `next_episode_ids` 只连接同一人物确有资料的后续决定，不表示用户选择后一定通向该结果，也不是游戏模拟分支。

## 校验

```bash
npm run validate:data
node --test data/validate-data.test.mjs
npm run build
```

首批 12 条的阶段提交使用 `npm run validate:data -- --milestone initial`；最终默认命令强制至少 36 条，不会因删掉案例静默退回首批门槛。自定义数据文件也必须带同目录的 `sources.json` 和 `review.json`：

```bash
node scripts/validate-data.mjs path/to/episodes.json
```

检查覆盖四种以上选择、三个 Demo 方向、两类必需负面结果、字段类型与来源绑定、URL 格式及来源类型一致性、明确未知与后续引用。校验离线运行，不把 HTTP 可访问或文字来源存在等同于事实准确。

## 人类审核与样本局限

当前 `human_review` 为 `pending`。AI 已按公开材料整理并核对，合并前由人类对照正文确认关键年份、行动和结果，记录 `reviewed_by`、`reviewed_on`，再将各条及汇总改为 `approved`。结构通过不替代该步骤。

部分 Nobel 等网站直接访问受限，已用搜索索引中的正文核对，索引中明确记为 `search_index`；这些条目须优先打开原页复核。公司与投资人材料存在宣传立场；自述存在回顾性选择。仅保留出处、定位和改写，不复制网页全文。

本集按事件选取，包含不适配、持续职位损失与关闭项目，但人物仍偏向有公开资料的知名者；**不能声称消除了幸存者偏差，不能据此计算成功率或最优人生**。同一个人的多个节点不是独立样本。

三个 Demo 方向是结构类比，不是现代中国教育与就业的代表样本。尤其“考研还是就业”含工作后读博、博士后及毕业后继续训练，和硕士统考差异显著；“大厂还是小公司/创业”也含项目退出与双轨创作。每条 `analogy_boundary` 已同步到消费端可见的 `unknowns` 和 AI 证据。

当前任务只交付数据与校验；游戏人生、积分和新版画像留待后续计划。
